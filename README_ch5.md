# Chapter 5 illustrative instance

`online_grouping/ch5.py` reproduces the deterministic sliding-window
grouping illustrated in Chapter 5 of the thesis, so that Figure 5.1
(`fig_grouping_result.pdf`) and the numbers of the illustrative
subsection come from code rather than from the notebook that produced the
original draft.

## Run

```bash
python3 -m online_grouping.ch5 --seed 4 --out results/ch5 \
    --figure results/figures/fig_grouping_result.pdf
# and copy the figure into the thesis:
cp results/figures/fig_grouping_result.pdf \
   ../thesis-overleaf/Thesis/figures/
```

Other seeds (`--seed 1, 17, 29, 57`, ...) give further instances of the
same family; the paper quotes seed 4.

## What it implements

* threshold-generated input plan: one GR task per refilled cycle, with the
  first cycle at `ceil((p_i(0) - p_ref) / delta_i)`;
* admissible execution days, eq. (5.18)-(5.19) of the chapter, with the
  safe deadline of eq. (5.6) excluding the pressure-floor crossing day
  (`ceil(crossing) - 1 - Delta_safe`);
* Model 1 window subproblems (cluster count minimisation subject to
  capacity `K_clus`), solved with Gurobi when the restricted licence
  allows, otherwise with `scipy.optimize.milp`;
* successor reference-date translation after each fixed task and adaptive
  window advancement, `w_next = min tau_n^0` over the pending tasks still
  inside the window;
* leakage accounting under both degradation forms (see below).

## Instance and results for seed 4

Ten compartments, `T = 30` days, `delta_i ~ U(0.012, 0.030)` bar/day,
`p_i(0) ~ U(3.21, 3.50]` bar, `p_ref = 3.2`, `p_min = 3.0`,
`L_win = 10`, `Delta_adv = 3`, `Delta_safe = 2`, `K_clus = 5`,
`c_set = 10` cost units. No delay bound applies to this instance: the input
plan is generated by the threshold rule, so every task starts on its own
reference date.

| quantity | value |
| --- | --- |
| input GR tasks | 21 |
| windows processed | 3, each solved to optimality |
| dispatch days | 6 (days 4, 7, 15, 19, 23, 25) |
| cluster sizes | 3, 4, 5, 2, 2, 5 |
| reduction vs one dispatch per task | 71.4 % |
| setup cost | 210 -> 60 cost units |
| advanced / unchanged / delayed | 9 / 2 / 10 |
| mean absolute displacement | 1.95 days (max 6) |
| delay slack to the safe deadline | 6 to 28 days |

The delay side dominates because advancement is capped at `Delta_adv = 3`
days while the safety deadline leaves 6-28 days of slack; displacements in
the thesis table are measured against the input reference date, whereas
the constraints bound them against the operational reference date
`tau_n^0`.

## Leakage

`leaked_mass` reports the ideal-gas leakage mass
(`kappa = 5.993` kg/bar for a 1 m^3 compartment) for both degradation
forms, which do not agree about what grouping does to leakage:

| form | input plan | grouped plan | change |
| --- | --- | --- | --- |
| constant rate, eq. (5.3) | 43.054 kg | 43.054 kg | 0.00 % |
| proportional (Chapter 4) | 45.048 kg | 44.965 kg | -0.18 % |

Under the constant-rate form the cumulated pressure drop over a fixed
horizon is independent of the refill dates, so grouping cannot change the
leaked mass. The change reported in the original draft (42.114 -> 42.696
kg, +1.38 %) only exists under the proportional form, and its sign is
instance-dependent: here it is negative.
